# 차량 설정 값 읽기 경로 조사 (2026-11-22, 0.5.0-test11)

K8(기아) 5W **순정 차량 설정 앱**(`com.android.vehiclesettings`, uid 1000 시스템 앱)이 각 항목을 어디에서 읽는지 조사했다.
코드 변경 없이 조사만 먼저 했고, 읽을 수 있는 것만 읽기 전용으로 연결했다. **차에 명령은 보내지 않았다.**

### 2.4 차량 라이브러리(BCM 등) — 일반 앱 불가

`smali-automotive` 에 `BCMManager`(차량 상태), `ClusterManager`(클러스터), `BluelightManager`, `AvmManager` 등이 있다.
클러스터·공조·시트·라이트·도어 값은 대부분 이쪽을 거친다.

- 상태는 BCM 방송과 콜백으로 넘어온다(예: `BCMManager$BCMDrivingStatus`, `BCMSpeedUnit`, `BCMLampStatus`, `ClusterManager$ClusterHandlerEvent`).
- 순정 앱 안에는 `get…Status`/`get…Value` 형태의 공개 getter가 많다(예: `getClusterThemeSelectedItem`, `getClusterWelcomeSoundStatus`, `getHUDDisplayHeight`, `getHeadUpDisplayEnableStatusForDBProvider`, `getEcoVehicle_CoastingGuide`, `getClusterIcyRoadWarningStatus`).
- **일반 앱에서는 쓰지 않는다.** 차량 버스에 붙는 값이고, 부르면 차량에 명령이 나간다. 읽기 전용으로도 공개 경로가 없다 → **불가**.

## 4. 이번에 연결한 것(읽기 전용)

- `HeadUnitInfo.vehicleProps()` — 차량 관련 시스템 속성 15개를 읽는다(2.2절). **쓰기 코드는 없다.**
- 이미 읽던 것: `drivemode_notification`(드라이브 모드 변경 알림), `seat_position_alert`(시트 위치 변경 알림),
  `persist.sys.setting.cluster`(클러스터 테마), `use_welcome_message`(웰컴 사운드).
- 화면 표시 규칙: 읽은 값이 **켜짐/꺼짐으로 확인된 항목**(드라이브 모드 변경 알림·시트 위치 변경 알림·웰컴 사운드)만 "켜짐/꺼짐"으로 쓴다.
  나머지는 "순정 값 N", 읽히지 않으면 "순정 연동 대기"로 보여 준다. 수집 당시 값을 고정으로 넣지 않는다.

# 5W 설정을 테마에서 볼·바꾸기 — 차 시험 순서

2026-11-22. 한 번 차에 가지면 끝까지 확인할 수 있게 순서를 정했다. **확인(y/N) 질문은 하지 않는다.**
쓰기 시험은 사용자 허락을 받은 뒤에 하고, 한 번에 하나씩만 바꾼 뒤 원래 값으로 되돌린다.

## 0. 준비 (차 방문 시)

1. 테마 APK 0.5.0-test1 설치(네메시스 USB 묶음). USB 를 꽂으면 `nemesis/install.sh` 가 알아서 설치한다.
2. `tools/car_capture.ps1` 실행 — 순정 설정 화면 7장과 설정 키 값, 로그를 모은다.
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\car_capture.ps1 -Serial <차량IP>:5555
   ```
   모이는 것: `private/vehicle/capture-<시각>/34~40-stock-settings-*.png`(순정 설정 화면),
   `29-stock-setting-values.txt`(키별 실제 값), `28-settings.txt`(설정 DB 덤프), `40-logcat-all.txt`.
3. **차에 아무 명령도 안 보낸다.** 수집 스크립트는 화면을 열기만 하고 값은 바꾸지 않는다.

## 1. 읽기 확인 (먼저 이것만)

테마(설정 → 각 분류)에서 아래 값이 설명서/순정 화면과 같은지 눈으로 비교한다.

| 분류 | 확인할 값 | 기대 |
|---|---|---|
| 버튼 | 사용자 버튼 ☆ (내비게이션) | 순정 화면의 고른 항목과 같은 번호가 보일지(값 번호 표기) |
| 버튼 | [∧]/[∨] 버튼, VOL/TUNE 노브 | 같은지 |
| 클러스터/HUD | 클러스터 테마 선택 | 순정 클러스터 테마와 같은 번호 |
| 일반 | 순정 시간 자동 설정, 순정 시간 표기 방식 | 순정 화면과 같은지 |
| 일반 | 화면 밝기(기기) | 순정 디스플레이 화면과 같은지 |
| 기기 연결 | USB/무선 폰 프로젝션 | 순정 기기 연결 화면과 같은지 |
| 사운드 | 고음/중음/저음, 전후/좌우 | 순정 사운드 화면과 같은지 |
| 차량 | 드라이브 모드, 클러스터 테마 | 같은지 |

- 못 읽은 항목은 화면에 **"순정 연동 대기"** 로 나와야 한다(빈칸이면 버그).
- `29-stock-setting-values.txt` 에서 키가 안 나오면 그 항목은 "읽기 불가" 로 정하고, 연동표 상태를 **불가** 로 바꾼다.

## 2. 쓰기 확인 (사용자 허락 뒤에만)

**전제**: 우리 앱에는 `WRITE_SETTINGS` 권한이 없다. 그래서 `Settings.System` 系 키는 **저장이 막힐 가능성이 높다.**
막히면 화면에 "차량이 이 앱의 쓰기를 막았습니다(WRITE_SETTINGS 없음)" 가 뜨고, `logcat -s K8Settings` 에
`denied writing <키>` 로 남는다. **이러면 실패로 기록한다(재시도하지 않는다).**

순서(각 단계 뒤에 원래 값으로 되돌린다):

| # | 항목 | 조작 | 되돌리는 방법 |
|---|---|---|---|
| 1 | 순정 시간 자동 설정 | 일반 → 순정 설정 연동(시험) → "순정 시간 자동 켜기" | 원래 상태(켜짐/꺼짐)를 보고 반대 버튼 |
| 2 | 순정 시간 표기 방식 | "순정 24시간" / "순정 12시간" | 원래 표기를 보고 반대 버튼 |
| 3 | 화면 밝기 | (추가하면) | 순정 디스플레이 화면에서 원래 밝기 |

- 스위치(**순정 설정 직접 변경(시험)**)가 **꺼져 있으면** 쓰기 버튼을 눌러도 **순정 설정 화면이 열린다**(쓰지 않는다).
  스위치를 켠 상태에서만 테마에서 직접 바꾼다.
- 시험이 끝나면 **스위치를 다시 끈다**(테마 저장값이 켜진 채 남으면 안 된다).

## 2-1. 버튼 선택지 대응 (0.5.0-test3에서 대응 미확인 → 차에서 확인)

테마의 버튼 설정 화면은 **현재 선택된 항목을 표시하지 않는다**(값 번호만 보여 준다).
이유: `btn_n_left` / `btn_n_right` / `button_settings_seek` / `tune_knob_function` 의 int 값이
어떤 선택지(경로 취소·내 차 위치 공유·날씨·라디오…)에 대응하는지 확인할 근거가 아직 없다.
차에서 아래 두 파일을 받아와 문자열 배열 순서와 대응시키면 표시할 수 있다.

```powershell
adb -s <차량IP>:5555 pull /system/app/ButtonSettings.apk
adb -s <차량IP>:5555 pull /system/app/ButtonSettings.odex
```

확인되면 `assets/index.html` 의 `STOCK_SETTING_SCREENS.buttons` 에 선택지별 `value` 를 넣고
`stockRowHtml()` 에서 고른 라디오에 `radio-circle` 채움 표시를 추가한다.


## 2-2. 차량 화면 읽기 확인 (0.5.0-test11)

테마의 차량 화면(분류 11개·하위 화면 32개)을 순정 차량 설정 화면과 나란히 본다.

| 분류 | 확인할 것 | 기대 |
|---|---|---|
| 운전자 보조 | 하위 화면 8개(주행 편의·전방 안전·스마트 크루즈 컨트롤·속도 제한·차로 안전·운전자 주의 경고·주차 안전·후측방 안전) | 줄 이름·설명 글·선택지 개수가 순정 캡처와 같은지 |
| 드라이브 모드 | 드라이브 모드 변경 알림 | 켜짐/꺼짐 또는 "순정 값 N" |
| 공조 | 터널 구간·기타 차단 구간·습기 발생 저감 | 읽히면 "순정 값 N" |
| 라이트 | 실내 무드 조명 | "순정 값 N" 또는 "순정 연동 대기" |
| 시트 | 시트 위치 변경 알림 | 켜짐/꺼짐 |
| 클러스터 | 클러스터 테마 선택 | "순정 값 N"(대응 미확인) |
| HUD·디지털 키·도어·편의 | 항목 이름·설명 글 | 순정 캡처와 같은지 |

확인 순서:

1. 테마 APK 0.5.0-test11 설치(네메시스 USB 묶음).
2. `powershell -ExecutionPolicy Bypass -File tools\car_capture.ps1 -Serial <차량IP>:5555`
   → `30-vehicle-value-paths.txt`(차량 속성·설정 키·차량 설정 DB 조회 결과), `29-stock-setting-values.txt`, `34~40-stock-settings-*.png`.
3. `30-vehicle-value-paths.txt` 맨 위에 `content://com.android.vehiclesettings.provider...` 조회가 붙어 있으면
   **일반 앱에서 차량 설정 DB를 읽을 수 있다.** 그때는 연동표 7-1절 상태를 "확인됨" 으로 바꾸고, 항목을 DB 에서 직접 가져오도록 바꾼다.
4. 테마 → 설정 → 차량 → 분류를 하나씩 눌러 본다.
   켜짐/꺼짐과 선택 표시는 **읽은 값으로만** 정하므로, 못 읽으면 "순정 값 N"·"순정 연동 대기" 가 나와야 한다(고정으로 미리 고른 항목이 있으면 버그).
5. 하위 화면에서 뒤로 가기를 눌러 분류 화면으로 돌아가는지 본다(왼쪽 메뉴는 그대로 보여야 한다).

이 절은 **읽기만** 한다. `content query`·`getprop`·`settings get` 만 쓰고, `setprop`·`settings put`·`content update` 는 쓰지 않는다.


## 2-3. 순정 내비 하단바(오버레이) 확인 (0.5.0-test12)

순정 내비가 맨 앞에 있을 때 뜨는 하단바 창(테마가 만드는 오버레이)이다. **읽기만** 한다.

| # | 확인할 것 | 방법 | 기대 |
|---|---|---|---|
| 1 | 미디어 칸 누르기 | 하단바 오른쪽 앨범 그림 또는 곡 이름 칸을 누른다 | 팝업(재생목록)이 **안 뜨고** 테마의 미디어 화면이 열린다. 지금 음원이 블루투스면 블루투스 음원으로 열린다 |
| 2 | 미디어 칸 왼쪽 그림 | 눈으로 확인 | 재생/정지 아이콘이 없고 앨범 그림(없으면 기본 그림)만 보인다 |
| 3 | 진행 막대 | 음악을 틀고 하단바를 본다 | 앨범 그림 오른쪽부터 화면 끝까지 가는 가는 줄이 보인다. 재생한 만큼 주황색, 남은 부분은 회색 |
| 4 | 좌우 스와이프 | 미디어 칸에서 왼쪽으로 길게(60px 이상) | 다음 곡. 오른쪽으로 길게 → 이전 곡. 짧게 누르면 1번(미디어 화면) |
| 5 | 경로 알약 | 길안내 중 하단바를 본다 | 남은 거리·도착 시간 다음에 구분선, **깃발, 목적지 이름**이 보인다 |
| 6 | 목적지 없을 때 | 경로 없음 상태에서 본다 | 깃발·목적지·구분선이 모두 숨고 빈 칸이 남지 않는다 |
| 7 | 긴 목적지 | "아리랑리조텔 속초점 정문 주차장" 처럼 긴 이름으로 | 글자가 잘려도 깃발은 계속 보이고, 글자는 흐르며 보인다 |

- 스와이프가 안 되면 `logcat -s K8HomeNavBar` 을 본다(버튼/커버를 누른 동작 이름이 `K8NavBar.action` 으로 넘어간다).
- 테마를 열 수 없을 때만 순정 블루투스 오디오 앱이 열린다(그때는 팝업이 아니라 별도 화면).

## 3. 되돌리기(안전 장치)

- 설정값은 언제든 **순정 설정 화면**에서 원래대로 바꿀 수 있다. 테마를 끄고(테마 앱 종료) 순정 화면에서 확인한다.
- 프로필 삭제·시스템 초기화·초기화 버튼은 테마에 넣지 않았다. 화면에도 나오지 않아야 한다.
- 로그에 남는 것: `K8Settings` 태그의 저장 성공/거부만. 개인 정보는 넣지 않는다.

## 4. 확인 안 되는 것(차 가도 못 보는 것)

| 항목 | 이유 |
|---|---|
| 5W 설정 앱 안의 저장소 키 전체 | 순정 설정 앱이 코드가 없는 APK(리소스만)라 실제 키는 차량 odex 에만 있음 |
| ADAS·공조·시트·라이트 값 | 클러스터/CAN 쪽이라 헤드유닛 경로가 없다 |
| 메시지 수신 필터·자동 회신 | 순정 블루투스 앱 영역 |
| 라디오 음질 | 순정 라디오 앱 영역 |
| 단위 설정 | 키를 찾지 못했다 |

→ 이 항목들은 연동표에서 **불가** 로 남기고, 테마에는 "순정 연동 대기" 로만 보여 준다.

## 2-4. 블루투스 곡 넘김 도우미·순정 곡 팝업 (0.5.0-test15)

설치: `deliverables/검수전/K8-ccNC-Home-NEMESIS-0.5.0-test15-USB.zip` 을 USB 루트에 풀어 NEMESIS Manager 로 설치한다.
이 패키지(`k8home.install`)에 테마 APK와 곡 넘김 도우미 서비스(`keys`, system uid, 소켓 `k8home.keys`)가 함께 들어 있다.

1. 설치 뒤 `cat /proc/net/unix | grep k8home.keys` 에 소켓이 보이는지, `/data/nemesis/logs/k8home.keys/` 에 기록이 생기는지.
2. 블루투스 음악 재생 중 테마로 지도를 열어 하단바 미디어 칸을 왼쪽으로 민다 → 다음 곡, 오른쪽 → 이전 곡(166은 앞부분이면 이전 곡, 아니면 처음부터).
   logcat `K8HomeKeys` 에 `helper 167 -> ok`.
3. 테마 미디어 화면의 이전/다음/재생 버튼도 같은 길로 동작하는지.
4. 곡이 바뀔 때 순정 곡 정보 팝업(오른쪽 분할 화면 OSD)이 바로 닫히는지(핸들 버튼으로 넘길 때 포함).
5. 문제가 있으면 NEMESIS Manager 에서 `k8home.install` 의 서비스만 끄면 된다(차량 설정은 바꾸지 않는다).

## 2-5. 차에서만 어긋나던 화면 (0.5.0-test16)

1. 홈 카드 글자("지도", 곡 이름, 아래 설명)가 PC 흉내 그림만큼 큰지, 홈 아래 페이지 점(─ ─ ─)이 보이는지.
2. 테마 미디어 화면: 이전/재생(일시정지)/다음 그림이 온전한지, "재생 목록"·"라이브러리"가 한 줄인지, 왼쪽 위 제목과 기기 아이콘이 떨어져 있는지.
3. 긴 곡 이름(하단바·홈·미디어 화면): 흐르는 동안 굵기가 바뀌지 않고, 곡 정보가 갱신돼도 처음으로 튀지 않는지.
4. 하단바 미디어 칸을 누른 뒤 주황 테두리가 남지 않는지.
5. 남는 차이는 WebView 원격 디버깅으로 계산된 스타일을 읽어 확인한다(AI_HANDOFF 0.5.0-test16).

## 2-6. 길안내 목록 펼치기/접기 버튼 (0.5.0-test17)

### 남은 스타일 차이는 WebView 원격 디버깅으로 읽는다

PC 흉내로 잡히지 않는 차이는 **차의 WebView 에 직접 붙어 계산된 스타일을 읽는다.**

```
adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>
```

- Chrome 에서 `http://localhost:9222` 를 열고 해당 WebView 탭의 **검사** 창을 연다.
- Console 에서 아래를 찍어 화면마다 비교한다.
  ```js
  (function(){var o=[];document.querySelectorAll('*').forEach(function(e){var r=e.getBoundingClientRect();
   if(r.width&&r.height&&r.top<720&&r.bottom>0)o.push([e.tagName+'.'+(e.className||'')+'#'+(e.id||''),Math.round(r.left),Math.round(r.top),Math.round(r.width),Math.round(r.height)].join(','));});return o.join('\n');})()
  ```
- `node tools/c30_preview.cjs` 로 만든 흉내 화면(`captures/c30/`, 1280×480 배율 1.5)과 나란히 놓고, 4px 넘게 다른 요소를 찾는다.
- 먼저 볼 곳: 홈·대기 화면 아래 페이지 막대 높이(흉내에서 12px 아래), 전체 앱 타일의 그림:글자 비율.
- 차 WebView 가 CSS.supports 를 모르는 탭에서는 `clamp()`·`min()`·`max()`·flex `gap` 이 **무시된 상태**로 계산된다.
  그 상태에서의 계산값과 PC 계산값을 비교하면 차에서만 어긋나는 이유가 바로 보인다.
